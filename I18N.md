# Internationalization (i18n)

The site is **French first**, with an English version. Translations live as static JSON files (`messages/{locale}.json`), written by hand for accuracy and brand voice, and served via [`next-intl`](https://next-intl.dev) with full SSG and per-locale SEO.

- French at `/` (default locale, no prefix)
- English at `/en`
- Browser language detection is **off** (`localeDetection: false`): every visitor lands on French and switches with the FR / EN toggle.
- The former `/es`, `/it` and `/de` URLs permanently redirect to `/` (see `next.config.ts`).
- `kepler-industries.com` (apex) permanently redirects (301) to `https://www.kepler-industries.com`, same path (see `next.config.ts`).

## File structure

```
kepler-industries-website/
├── i18n/
│   ├── routing.ts          # Locale list (fr, en), default (fr), prefix strategy
│   ├── navigation.ts       # Locale-aware <Link>, useRouter, usePathname
│   └── request.ts          # Loads messages/{locale}.json per request
├── messages/
│   ├── fr.json             # ⭐ Source of truth — write French here first
│   └── en.json             # English translation, same shape
├── proxy.ts                # next-intl middleware (Next.js 16 convention)
└── app/
    ├── layout.tsx          # Pass-through root layout (required by not-found.tsx)
    ├── not-found.tsx       # Site-wide 404 (French, with a link to /en)
    └── [locale]/
        ├── layout.tsx      # <html lang>, shared metadata
        └── page.tsx        # canonical, hreflang, JSON-LD
```

## Day-to-day

1. Edit `messages/fr.json`.
2. Mirror the same key in `messages/en.json` — keys, namespaces and array shapes must stay **identical**.

Server components use `getTranslations("Namespace")`, client components `useTranslations("Namespace")`.

Highlighted words in section titles use a `<hl>` tag rendered with `t.rich()`:

```json
{ "title": "Ce qu'on a <hl>construit</hl>" }
```

```tsx
t.rich("title", { hl: (chunks) => <span className="hl">{chunks}</span> })
```

Arrays of objects (`Projects.items`, `Services.items`, `Process.steps`…) are read with `t.raw()`. Non-translated project data (URL, accent color, stack, layout) lives in `META` inside `components/projects.tsx`.

## Gotchas

### Apostrophes before `<`, `{`, `}`, `#` (ICU escape rule)

A bare `'` directly followed by `<`, `{`, `}` or `#` opens an ICU quoted section. Double it (`''`) in that case only. Quick audit:

```bash
grep -nE "'[<{}#]" messages/*.json
```

### Brand names

Project names (`Powr`, `Rituel`, `Kepler Orbit`, `Littoral Food`, `Kepler Business`, `Saun'Activ Océan`…) and tech tags (`Next.js`, `Expo`, `Swift`…) are never translated.

## Adding a language

1. Copy `messages/fr.json` to `messages/{locale}.json` and translate every value.
2. Add the code to `locales` and `localeLabels` in `i18n/routing.ts`.
3. Add its Open Graph locale in `OG_LOCALES` (`app/[locale]/layout.tsx`).
4. If it was one of the retired locales, remove it from `RETIRED_LOCALES` in `next.config.ts`.
